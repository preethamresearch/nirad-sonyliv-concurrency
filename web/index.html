How it works

Heartbeats prove a client is alive.
They do not prove anyone is watching.

82% of foreground pauses keep emitting heartbeats. Any model that treats a heartbeat as activity counts paused-but-open time as viewing — exactly the over-count this exists to remove.

◧

Intent, not presence

Activity opens only on an explicit transition — play, resume, foreground — and closes on pause, background or session end. Transitions collapse, never pair.

◔

Liveness as a failure detector

Silence beyond 120s means the client died without telling us. That threshold is 3× the measured 40s cadence — the data dictionary says 60s and is wrong.

▦

Deltas, not a minute grid

Two rows per interval regardless of duration: 31,521 against the 145,821 a per-minute explosion needs, and the gap widens as sessions lengthen.

Engineering log

Seven bugs we shipped, caught, and wrote down.

Most were caught by building something adversarial rather than by reading the code again. The full account is in the README.

Silent corruption

The sealed-day loader bound CSV columns by position

A wider file does not fail — it shifts every value one column left and loads platform into country. Worse, run_sealed.py had its own copy of the insert, so hardening the shared loader did nothing for the command that actually runs on judging day.

The verifier was the fragile part

Our correctness gate only worked on the sample file

It hardcoded a header name, so a renamed column made it crash — the loader would ingest a drifted schema correctly and the thing meant to prove it right would die.

Off by 24%, in our favour

The obvious concurrency query is wrong

The natural interval-overlap query returns 2,353 where the truth is 3,090. An interval opening and closing inside one minute cancels itself out. The wrong number is plausible, and it errs in the direction that flatters you.

A filter that lies

Two of four dashboard filters were silently ignored

Selecting a category narrowed nothing and the headline did not move. A reader would have trusted it. Each view now declares which filters it can honour — an ignored filter is worse than an absent one.

Confidently wrong

Three of four compression hypotheses were wrong

DoubleDelta looks obviously right for 40-second heartbeats. It is wrong here — rows are ordered by session, not time. Plain Delta is 17.1% smaller. ZSTD(6) everywhere bought 0.4% for ~20% more insert CPU.

What we would tell SonyLIV

The most valuable findings point upstream.

Emit an explicit playback state

pause and resume hide inside heartbeat events, so every consumer reconstructs intent differently. One authoritative field removes a whole class of disagreement between teams reporting the same metric.

Add a device instance id

82 sessions genuinely stream on two devices at once and the schema cannot express it, so any model must double-count or under-count. That matters directly for concurrency-based licensing.

Fix the documented cadence

The dictionary says 60s; measured is 40.0s at p90 on all ten platforms. Any gap threshold derived from the docs is calibrated 50% too loose.

Normalise language at the producer

Naive attribution reports 80% of sessions as unknown. The true figure is 0.5% — the difference between “we have no language data” and “we have it for 99.5%”.
